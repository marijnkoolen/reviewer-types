  **Outcome, decomposed rather than modeled as one joint object.** A full Dirichlet-multinomial or multinomial-cluster model over the whole compositional vector is the theoretically clean option but expensive to fit with multiple hierarchical groups, and a categorical-cluster outcome forces interpretation through an abstract cluster label rather than "share of Content." Primary approach: **one hierarchical Beta regression per main category's `prop__label`** (7 parallel models, `TESTED_LABELS`-style), directly extending the frequentist regressions items 2/10 already validated — same outcome variable, now Bayesian + hierarchical + with the new fame/experience covariates. A joint model is kept as an explicit **optional last step**, not the starting point (see below).

  **Two lagged accumulation covariates, at BOTH book and author level** (chat, 2026-08-20): a new, unreviewed book by an unknown author doesn't draw the same attention as a new book by a famous author, so book fame alone misses a real mechanism. **First-pass fame is count-based only**: `log1p(prior review count)`, computed only from reviews dated strictly before the current one, sorted chronologically per `work_id` and separately per `author_id` — count-based is the more meaningful and less troublesome signal to start with (rating-based fame deferred, see follow-ups below). Cold-start (a book's or author's first few reviews, no prior review history): `log1p(0)=0` handles this naturally as a continuous covariate, no special missing-data machinery needed. **Known collinearity, not preemptively engineered around**: book fame and author fame will correlate, especially for an author's later books (author fame is partly built from earlier book fame) and are identical at an author's debut book (both zero). Deliberate choice: include both as constructed, fit the model, check VIF / posterior correlation between the two coefficients afterward — if they're fighting each other too much to interpret separately, that's a finding to report, not a reason to orthogonalize by construction (e.g. redefining author fame as "prior reviews of the author's *other* books only") before even looking.

Postponed because count-based fame is the more meaningful signal to get right first, and it's not yet known whether rating-fame adds anything beyond it.
    - ~~*Fame × genre random slope*~~ — **promoted to item 10** below (chat, 2026-08-20): the first-pass fixed-effect fame coefficients turned out interesting enough (opposite-signed for `Author`/`Style`, largest-magnitude effects on `Content`/`Reader_response`) to justify asking whether they differ by genre now rather than later.

  **Random-effect structure, kept deliberately small**: random intercepts for platform (8 levels) and genre (10 levels) — not work/author/reviewer identity, which would make this a genuinely hard crossed-random-effects sampling problem at this cardinality (109K works, tens of thousands of authors, 227K reviewers) for no real gain, since fame/experience are exactly the mechanism through which those identities should matter here, not an additional identity effect on top. A random slope on year by platform lets "does the temporal trend differ by platform" fall out of partial pooling instead of needing a separate crosstab.

  **Tooling and fitting strategy**: PyMC via `bambi`'s formula interface (`prop__Content ~ year_c + length_c + book_fame + author_fame + reviewer_experience + (year_c|source_id) + (1|nur_genre)` as implemented — `(year_c|source_id)` already gives platform both a random intercept and a random slope on year in bambi/lme4 syntax, correlated, so no separate `(1|source_id)` term is needed alongside it) — Python-native, consistent with the rest of the toolchain, formula syntax saves substantial hand-written model code over raw PyMC. Prototype on a subsample first (same de-risking pattern as items 5/7), fit with ADVI for speed (`bambi`'s `inference_method="vi"` returns the raw PyMC `MeanField` approximation, not an `InferenceData` — posterior samples need an explicit `.sample(draws)` call on it afterward), sanity-check the Bayesian point estimates against the already-published frequentist OLS coefficients for the same labels (done — see results above; only then decide whether to scale to the full corpus or run full NUTS for a real posterior instead of ADVI's approximation).

  **Optional last step, only if the 7-model version proves informative first: joint model restricted to 4 categories** (`Reader_response`, `Content`, `Style`, `Author` — chat, 2026-08-20) — the four with both real literary-critical weight and enough prevalence to support it; `Classification`/`Recommendations` are more paratextual, `Other_works` too sparse to be worth the added cost. Technical note that rules out a literal Dirichlet-multinomial here: main-category labels aren't mutually exclusive at the sentence level (a sentence can carry both `Content` and `Reader_response`), so `prop__label` values don't sum to 1 across categories the way a true compositional/simplex vector needs to — forcing that constraint would impose an exclusivity assumption the data doesn't have. Instead: a **multivariate model on the four logit-transformed shares**, correlated through a shared multivariate-normal random-effect structure — still hierarchical, still captures "when Content rises within a review, does Reader_response tend to fall" (the actual thing "joint" is trying to buy), without the false exclusivity assumption.

  **DECISION (chat, 2026-08-20): not pursued, arc closed.** Items 9–12 ended up answering the joint model's own motivating question — does Content trade off against Reader_response — *indirectly but repeatedly*: the two move in opposite directions across every covariate fit across this whole arc (length, time, reviewer experience, book fame, author-fame concentration), which is already strong informal evidence of a real compositional trade-off. What the joint model would add on top is narrower than it first looks: a *formal residual correlation* between the two, net of those shared covariates — a real but marginal question at this point, not a new discovery waiting to be unlocked. There's also a technical cost specific to this project's tooling, not just an effort cost: the mean-field ADVI used throughout items 9–12 assumes independent posterior components by construction, a poor fit for a model whose entire point is estimating a correlation — doing this properly would mean switching to full NUTS, exactly the heavier inference item 9 scoped out ("not full-corpus MCMC"), and a materially bigger step up than anything items 10–12 needed (all of which reused the same fast, already-validated univariate machinery). Conclusion: the Bayesian-modeling arc (items 9–12) is complete as of 2026-08-20; revisit the joint model only if a future question specifically needs the formal residual-correlation number and can't be answered by the cheaper indirect route that's already been run four times over.

## 0b. Correcting for model error — now unblocked

**On the "20×20 confusion matrix" question**: no, that's not meaningful here, and it's not just a data limitation — it follows from how the model is built. MaChAmp trains one binary present/not-present task per category, so there are 20 independent binary classifiers, not one 20-way classification. A joint confusion matrix presumes a single true class competing against 19 others for each item; that's not the decision the model is making. What *is* meaningful, and what the correction methods below actually need, is a **2×2 confusion matrix per category** (TP/FP/FN/TN, computed independently per label) — which is what's implemented at [`src/correction/confusion_matrix.py`](src/correction/confusion_matrix.py) and written to [`results/correction/confusion_matrix.csv`](results/correction/confusion_matrix.csv), joining `data/ground_truth-test_set.tsv` (2,326 sentences) against `data/predictions-test_set.tsv` (2,323 sentences; 3 test sentences have no matching prediction row, dropped — negligible, 0.13%).

Consider treating these as case studies (matching the "too-sparse-to-model" categories already flagged for gold) rather than for quantitative claims at scale, unless/until the model itself improves on them.

**Correction methods** (now directly computable from the table above):

1. **Aggregate/prevalence-level correction** — for questions that only need corpus-level or group-level rates (occurrence §2, genre/platform/temporal prevalence trends), apply the Rogan–Gladen misclassification correction per label:
   `p_corrected = (p_observed + specificity − 1) / (sensitivity + specificity − 1)`,
   with the confusion matrix's own sampling uncertainty (it's from only 2,323 test sentences, so especially wide for the rare labels) propagated via bootstrap into the corrected estimate's CI.

2. **Instance-level correction** — co-occurrence (§3), contiguity (§4), order (§5), and the typology clustering (§6) need the actual per-sentence label *set*, not just a corpus-wide rate. Since predictions are hard 0/1 with no probabilities, the plan is a measurement-error / latent-class approach: treat each observed predicted label as a noisy proxy for latent truth, use the per-label sensitivity/specificity above as the error model, derive a posterior P(true label = 1 | predicted label) per sentence per label, then **multiple-impute**: draw several plausible corrected label-sets per review, rerun each downstream analysis across imputations, pool with Rubin's rules so every silver-set result carries explicit model-error uncertainty.
   - Per-label independence is the right granularity here, not a simplification we're settling for — it matches how the model actually makes its 20 separate binary decisions. The one thing this doesn't capture is *correlation between which sentences get which errors* (e.g., a sentence the model gets wrong on `Content--Narrative` might be more/less likely to also be wrong on `Content`) — worth a quick diagnostic (correlate the per-label error indicators on the test set) before assuming independence is harmless, but not a blocker.
   - Still enforce the parent-implies-child hierarchy constraint post-imputation (sub-category corrected to 1 ⟹ parent main category forced to 1).
   - Probability/logit scores from the model, if obtainable, would still improve on this (calibration, soft labels) — worth asking, but no longer blocking since we have a working hard-label correction path.

## 9. Reviewer consistency

- Gold: 51 reviewers with ≥2 reviews (excl. `platform_1`, max 8). Silver: 226,928 reviewers — recompute the multi-review pool size once loaded, almost certainly orders of magnitude more powered.
- Variance-partitioning (e.g. PERMANOVA on the review-distance matrix with reviewer, work, author, genre, platform as factors) to compare how much each explains — run on gold as a first pass, repeat on corrected silver for the real answer.
- `platform_1` excluded from any `user_id` term throughout, both tracks.

## 10. Temporality

- Normalize dates first (both files); reviews with no date excluded from this axis (~89 gold, ~43,327 silver).
- Check platform-by-date overlap before trend analysis in both tracks.
- Category-prevalence trends over time — silver's much longer effective run and larger per-year N make this far more viable than gold alone; gold's 1999–2022 span is real but thin in early years.

## 11. Ratings

- `0.0`/blank ratings = missing, confirmed — exclude, don't treat as a real low score.
- Relate category composition/cluster membership to rating (ordinal regression/correlation), watching the length↔rating and length↔category-count confound.
- Silver, once corrected, gives much more power here too, especially for rare categories' relationship to rating.

## 12. Phased roadmap

**Phase A — gold-set methodology & validation (can start now, no dependencies).**
Build the shared data layer (§1) and run §2–11 on the 1,152 gold reviews. This validates every method on trusted labels, gives real (if small-N, already-flagged-as-limited) answers for book/author/reviewer/temporal/rating questions, and produces the reference results that silver-set findings will later be checked against for replication.

**Phase B — correction pipeline: done and validated.**
Both correction methods are implemented ([`src/correction/prevalence_correction.py`](src/correction/prevalence_correction.py), [`src/correction/imputation.py`](src/correction/imputation.py)) and validated by synthetically corrupting the *known-true* gold sentence labels at each label's own measured error rate, then checking whether correction recovers the real gold prevalence better than the naive (uncorrected) corrupted estimate — [`src/correction/validate_pipeline.py`](src/correction/validate_pipeline.py), results in `results/gold_correction_validation_*.csv`.

- **Aggregate correction (Rogan–Gladen)**: essentially perfect. Mean |bias| drops from 0.0070 (naive) to 0.0001 (corrected) across all 20 labels, with the bootstrap CI hitting 100% coverage at the nominal 95% level, and no meaningful difference between `WEAK_MODEL_LABELS` and the rest — the aggregate method is robust even for the weak classifiers. Use this whenever a question only needs a corpus- or group-level rate.
- **Instance-level correction (multiple imputation + Rubin's rules)**: mean |bias| 0.0057 vs. naive 0.0069 — a real improvement, and most labels are well-calibrated (coverage 0.7–1.0). Getting here took three iterations, each one an actual validated failure caught before touching silver data, not a hypothetical: (1) drawing each label independently then forcing `main=1` whenever any child sub=1 compounds false positives across several children (Reader_response has 6) into +0.15–0.17 bias; (2) combining children's evidence via noisy-OR *before* drawing has the identical expected value to (1), so it didn't help; (3) drawing independently and suppressing the conflicting sub instead of forcing main up fixed the mains but pushed −0.14 bias onto the subs. The version that shipped draws main first from its own posterior, then draws each sub conditional on its main's draw (deterministic 0 if main=0; otherwise drawn using the *conditional* prior P(sub=1|main=1) and Se/Sp measured specifically on the main=1 test-set subpopulation, in `results/correction/confusion_matrix_conditional.csv`, since a classifier's error rate isn't the same on "obviously unrelated" true negatives as on "related but wrong subtype" ones).
  - **Known remaining limitation**: `Content--Narrative` and `Reader_response--Evaluation_of_quality` (conditional prior ~0.86 and ~0.55 — the two subs where "most of the parent category IS this subtype") still show a residual ~−0.03 to −0.04 bias in the per-sentence imputed values specifically, most likely because the synthetic validation corruption applies one uniform error rate per label while the real classifier's error rate demonstrably differs between easy and hard true-negative subpopulations. **For these two labels, prefer the aggregate Rogan–Gladen prevalence over the per-sentence imputed values** for any silver-set claim that only needs a corpus-level rate; the aggregate method has ~0 bias for them too.
- The sentence-level co-occurrence recovery check (a secondary, illustrative validation beyond prevalence) shows imputation moves co-occurrence estimates toward the true rate versus the naive corrupted data for the tested label pairs, though with more noise than the prevalence numbers alone would suggest — treat instance-level structural claims (co-occurrence, contiguity, order) at silver scale as needing wider uncertainty bars than aggregate prevalence claims, consistent with multiple imputation's whole design intent.

**Phase C — large-scale corrected analysis (in progress).**
Re-run §2–11 on the silver set, restricted to `FICTION_GENRES` and excluding `WEAK_MODEL_LABELS` throughout (§0b) — 466,973 reviews / 5.2M sentences survive both filters (`src/common/silver_data_prep.py`). Done so far: §2 occurrence (Rogan-Gladen corrected), §3 co-occurrence, §4 contiguity, §5 order, §6 typology clustering, §7 genre/platform, §8–9 book/author/reviewer similarity (scalable redesign, item 5 above), §10 temporality, §11 ratings — all raw/uncorrected except §2, which validates the correction pipeline on real (non-synthetic) data for the first time. Not yet done: instance-level (multiple-imputation) correction applied to §3–6 at silver scale (raw versions are done; the corrected versions need a subsample given the compute cost — M imputations × permutation-heavy methods on 5.2M sentences wasn't attempted this pass), and §8–9's comparative PERMANOVA specifically (the pairwise similarity tests are done; the variance-partitioning decomposition still needs its own scalable redesign, same dense-matrix problem).

Engineering notes worth keeping for future large-scale work in this project: (1) `prevalence_correction.py`'s bootstrap was rewritten from index-array resampling to direct Binomial sampling — mathematically identical for resampling a proportion's mean, ~11x faster, and necessary at this scale (a naive `(n_boot, n)` index array is untenable at n~467K). (2) Several gold scripts' per-review Python loops (contiguity's null lookup, order's transition counting, co-occurrence's permutation) needed vectorized rewrites for silver scale — same statistical method, restructured for cost; see `src/14-16_silver_*.py` docstrings for the specific vectorization used in each case. (3) Caught one real methodological bug this way: applying the confusion matrix's sentence-level correction to Phase A's review-level "≥1 sentence" prevalence statistic (a different, higher-baseline quantity) produced nonsense (a couple of labels "corrected" to 100%) — fixed by keeping sentence-level (corrected) and review-level (raw-only, no validated correction exists for it) as separate reported quantities. (4) The raw metadata has 3 review_ids each attached to two conflicting rows (one exact duplicate, two with different `work_id`/genre) — deduplicated (keep-first) in `silver_data_prep.py`, affects 6 of 670,924 rows.

**Replication results so far** (comparing silver-raw against Phase A gold, `results/01_occurrence/silver_vs_gold_occurrence.csv` and by inspection elsewhere): co-occurrence, contiguity, order, and the 8-cluster typology (down to matching cluster *profiles*, not just cluster count) all replicate closely — strong validation that Phase A's structural findings aren't small-N artifacts. Two do not replicate cleanly and are worth flagging prominently rather than quietly averaging away: (a) `Literary_fiction`'s independent rating penalty, gold's single strongest ordinal-regression predictor (coef −1.41), shrinks to coef −0.115 at silver scale (still "significant" only because n≈437K makes almost anything significant) — the raw per-platform gap gold reported (Literary_fiction rating ~1 point below other genres on every platform) is gone or reversed on most silver platforms. Gold's finding looks like it was a small-sample artifact, not a robust population effect. (b) Rogan-Gladen correction, which had ~0 bias in Phase B's synthetic validation, does not uniformly outperform the raw estimate on real silver data (§2 above) — real predictions don't guarantee the held-out test set's error rate transfers uniformly to the full corpus the way a controlled simulation does; the correction still adds a valid CI, which is real value, just not a bias-free point estimate in every case.
